# Government compliance

**MunicipalOS holds no certification, authorization or attestation of any kind today, and
nothing in this repository should be presented to a customer as proof of compliance.** What
exists is the _structure_: the product is being built so that each requirement a municipality is
likely to impose has a named control, a place in the code or process where it lives, evidence
that can be shown to an assessor, and an honest status.

This document is the index. It is engineering guidance, not legal advice; each item marked
**Counsel** needs review by a lawyer, and each item marked **Assessor** can only be satisfied by
an independent third party.

Dates and program details below were checked in November 2026 and change; re-verify before
relying on them in a proposal.

## 1. What applies to a municipal SaaS vendor

| Requirement                                                                            | When it applies                                                                                                  | What it demands                                                                                                                                                                                                                                                                                                   | Where we stand                                                                                                                                                                                                                                                                   |
| -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ADA Title II web rule** (28 CFR Part 35, Subpart H)                                  | Every state and local government customer, for their websites and mobile apps — including ones a vendor provides | WCAG 2.1 Level AA. An April 2026 interim final rule extended the dates: reported as April 26, 2027 for entities of 50,000+ and **April 26, 2028 for entities under 50,000** and special districts (our target market). Confirm against the Federal Register text. Existing ADA obligations apply in the meantime. | Built to WCAG 2.2 AA (a superset). Automated scans on every page in CI. **Manual and assistive-technology testing not done.** See [accessibility conformance](compliance/ACCESSIBILITY_CONFORMANCE.md).                                                                          |
| **Section 508 / VPAT**                                                                 | Procurements commonly ask for an Accessibility Conformance Report (VPAT 2.x)                                     | A criterion-by-criterion conformance report                                                                                                                                                                                                                                                                       | Tracker started; an ACR can be issued only after manual testing, ideally by an independent auditor (**Assessor**).                                                                                                                                                               |
| **GovRAMP** (formerly StateRAMP) / **FedRAMP**, and state programs such as **TX-RAMP** | Increasingly written into state and local cloud contracts; varies by state and by data sensitivity               | Security controls based on NIST SP 800-53, assessed by an accredited third party, with continuous monitoring                                                                                                                                                                                                      | Controls mapped by family in the [control matrix](compliance/CONTROL_MATRIX.md). Required level depends on each customer's solicitation. No assessment started (**Assessor**, **Owner decision** on hosting — a GovRAMP/FedRAMP-authorized cloud is effectively a prerequisite). |
| **SOC 2 Type II**                                                                      | Frequently requested by cities that do not require GovRAMP                                                       | Audited security/availability/confidentiality controls over a period                                                                                                                                                                                                                                              | Not started. Shares most evidence with the control matrix (**Assessor**).                                                                                                                                                                                                        |
| **State public records laws and records retention schedules**                          | Every customer; rules differ by state                                                                            | Records kept for the scheduled period, producible on request, not destroyed while subject to a hold, destroyed only under an approved schedule                                                                                                                                                                    | Structure built: retention schedules, legal holds, disposition with approval, complete-record export, append-only history. | **State data breach notification laws**                                                | Every customer                                                                                                   | Timely notice to the municipality (and through it, residents and regulators)                                                                                                                                                                                                                                      | [Incident response plan](compliance/INCIDENT_RESPONSE.md) drafted; contract terms and contacts not set (**Counsel**).                                                                                                                                                            |
| **State privacy and government data practices acts**                                   | Varies                                                                                                           | Notice, purpose limitation, access/correction, limits on sharing                                                                                                                                                                                                                                                  | Privacy statement template on every city site; data inventory maintained; no sale or third-party sharing.                                                                                                                                                                        |

Not built.                                                                                                                                          |
| **HIPAA**                                                                              | Only if protected health information is handled                                                                  | —                                                                                                                                                                                                                                                                                                                 | **Out of scope by design.** Forms warn against sensitive personal information.                                                                                                                                                                                                   |
| **CAN-SPAM / TCPA**                                                                    | Email and (future) SMS notifications                                                                             | Transactional-only messages, consent for texts, opt-out                                                                                                                                                                                                                                                           | Email is transactional only. SMS not built; needs consent capture first.                                                                                                                                                                                                         |
| **Election, tax, utility billing rules**                                               | Only with those modules                                                                                          | —                                                                                                                                                                                                                                                                                                                 | Not in scope.                                                                                                                                                                                                                                                                    |

## 2. How compliance is built into the system

These are product structures, each with tests, not policies on paper.

| Structure                                                       | What it does                                                                                                                                   | Status                                                                  |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Tenant isolation                                                | Membership gate, PostgreSQL row-level security, composite tenant keys                                                                          | Built, tested at API and SQL level                                      |
| Least-privilege roles                                           | Per-city roles and permissions; department scoping; access review screen; nobody can change their own access                                   | Built, tested                                                           |
| Append-only audit log                                           | Every change, sign-in, denial and export, with actor, time, address and request id; cannot be edited or deleted by the application; CSV export | Built, tested                                                           |
| Append-only record history                                      | Complete timeline per record, internal vs. public visibility                                                                                   | Built, tested                                                           |
| Data classification                                             | Every table classified public / internal / sensitive / restricted; public endpoints return allow-listed fields only                            | Built, tested ([data inventory](compliance/DATA_INVENTORY.md))          |
| Records retention schedules                                     | Per-city retention period per record type, with the legal citation                                                                             | Built, tested                                                           |
| Legal holds                                                     | A held record cannot be dispositioned; placing and releasing are audited                                                                       | Built, tested                                                           |
| Disposition                                                     | Records past retention are listed for review; personal data is redacted only on an authorized person's action; never automatic                 | Built, tested                                                           |
| Records export                                                  | Complete record as a file for public records requests and audits; every export audited                                                         | Built, tested                                                           |
| Session controls                                                | Idle timeout, absolute expiry, server-side revocation, system-use notice at sign-in                                                            | Built, tested                                                           |
| Upload safety                                                   | Type sniffing, re-encoding, metadata (GPS) removal, size and count limits, tenant-scoped storage keys                                          | Built, tested                                                           |
| Transport and browser hardening                                 | Nonce-based Content-Security-Policy, frame denial, no third-party scripts, no caching of personal data                                         | Built, tested                                                           |
| Accessibility by default                                        | Shared accessible components; brand colours forced to AA contrast; automated scans block regressions                                           | Built; manual testing pending                                           |
| Resident statements                                             | Accessibility and privacy pages on every city site, with the city's own contact details                                                        | Built (template — **Counsel** review per city)                          |
| Human authority                                                 | No automated system approves, denies, publishes or dispatches; content needs an authorized approver                                            | Built for content; rule recorded for permits and AI                     |
| Multi-factor authentication                                     | —                                                                                                                                              | **Not built.** Blocked on identity provider choice (**Owner decision**) |
| Encryption at rest, backups, monitoring, vulnerability scanning | —                                                                                                                                              | **Not built.** Arrive with hosting (**Owner decision**)                 |

## 4. Working rules for engineers

1. A new table is not done until it has a classification, RLS, least-privilege grants, a
   retention record type (or a written reason it is not a record) and an entry in the data
   inventory.
2. A new mutation is not done until it writes an audit event.
3. A new page is not done until it is in the automated accessibility scan and has been used
   with the keyboard alone.
4. Nothing ships that loads third-party scripts, trackers or fonts.
5. Never write "compliant", "certified" or "authorized" about MunicipalOS in code, docs, UI
   or marketing until an assessor has said so in writing.
6. New categories of data (payments, health, criminal justice, minors) need a compliance
   decision recorded in DECISIONS.md _before_ any code is written.
